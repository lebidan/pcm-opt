# A geometric redundant PCM for RM(128,64)

`codes/rm.128.64.geom.mat` is a redundant base PCM for the same RM(3,7) code
as `codes/rm.128.64.mat`. Its 135 weight-16 checks are arranged in nine groups
with a large shared support in each group. Algorithm 1 can factor those
supports through nine auxiliary variable nodes.

| Matrix | Size | Rank | Edges |
|---|---|---:|---:|
| Geometric redundant base | 135×128 | 64 | 2160 |
| After Algorithm 1 | 144×137 | 73 | 1296 |

The optimized PCM has girth 6, 65536 six-cycles and η̄_min = 28. Its 128
transmitted VNs have degree 9 and its nine auxiliary VNs have degree 16.
The auxiliary VNs carry zero channel LLR. The code still has dimension 64
and minimum distance 16. This is an alternative construction; it does not
reproduce the paper's exact 141×141 PCM.

## Construction

Identify the transmitted coordinates with the binary vectors of F₂⁷,
represented by integers 0 through 127. RM(3,7) is self-dual, and its
minimum-weight dual words are the indicators of affine 4-dimensional flats,
each containing 16 points [1].

Choose nine 3-dimensional subspaces U_i with pairwise intersection {0}.
Their explicit bases appear in the recipe below. For each U_i, enumerate its
16 affine cosets C_i,0, …, C_i,15, with C_i,0 = U_i. The union of C_i,0
and any other coset is an affine 4-flat. Use its indicator as a parity check:

    h_i,j = 1_(C_i,0) + 1_(C_i,j),    j = 1,…,15.

These are valid weight-16 checks of RM(3,7). The resulting 9×15 = 135 rows
have rank 64, verified against the supplied code. Independent checks are
placed first, followed by the remaining redundant checks in their original
order. This fixes the row order used by Algorithm 1's deterministic tie rule.

Within one group, all 15 checks contain the same eight-point anchor C_i,0.
Algorithm 1 introduces an auxiliary parity y_i for that anchor, producing:

    y_i + sum(x_v for v in C_i,j) = 0,    j = 0,…,15.

There are now 16 weight-9 checks per direction, hence 144 rows and 1296 edges.
Rows in one group share only y_i, since the cosets are disjoint. Cosets from
different directions meet in at most one point, since U_i ∩ U_j = {0}.
Therefore two rows never share two VNs, and there are no 4-cycles.

Eliminating y_i recovers the original anchor-plus-coset checks. Every y_i is
uniquely determined by its anchor, so the extension represents exactly the
original code. The rank increases from 64 to 73 while the number of columns
increases from 128 to 137; the dimension remains 64.

## Relation to finite geometry

The nine directions form a partial 3-spread of F₂⁷, or a partial plane
spread of PG(6,2) in projective terminology [2]. Taking all their affine
cosets gives a resolvable 2-(128,8,1) packing: each direction partitions the
128 points into sixteen blocks, and each pair of points belongs to at most
one block. Some pairs are uncovered, so this is not a balanced 2-design.
Adding one auxiliary point to every block in a parallel class gives the
optimized PCM's incidence matrix.

The references describe these geometric ingredients and their connection
to Reed–Muller parity checks; they do not establish novelty of this particular
nine-direction PCM.

## Reproduction

From the repository root, apply the existing optimizer to the supplied base:

```sh
julia --project scripts/pcm_i.jl codes/rm.128.64.geom
```

The result is `results/rm.128.64.geom.pcm1.mat`, with the optimized matrix in
`H`, the 135×128 base in `H_base`, and columns 129–137 in `puncturing_set`.
The original encoder and its inverse are retained.

The supplied reference run uses flooding NMS (α = 0.7), 20 iterations and LLR
saturation at 128. It gives FER 0.11272 at 3 dB and 0.00754 at 4 dB.
To repeat it after generating the optimized PCM:

```sh
cd sim
julia --project -t 16 scripts/simulate.jl config/rm.128.64.geom.pcm1.yaml
```

To regenerate the base file itself, save the following as a Julia script and
run it with `julia --project <script>`, from the repository root. It copies
`G`, `Ginv`, `n`, `k`, `dmin` and the display name from the original code file,
replacing only `H`.

```julia
using PCMOpt, MAT

bases = [(13,38,86), (12,20,70), (19,36,66), (6,26,99), (15,35,68),
         (11,54,71), (1,46,88), (25,41,67), (7,57,80)]
independent, redundant = BitVector[], BitVector[]
for (a,b,c) in bases
    U = [0,a,b,a⊻b,c,a⊻c,b⊻c,a⊻b⊻c]
    seen, cosets = falses(128), BitVector[]
    for x in 0:127
        seen[x+1] && continue
        h = falses(128)
        h[[x⊻u for u in U] .+ 1] .= true
        seen .|= h
        push!(cosets, h)
    end
    for C in cosets[2:end]
        h = cosets[1] .⊻ C
        if rank_gf2([independent; [h]], 128) > length(independent)
            push!(independent, h)
        else
            push!(redundant, h)
        end
    end
end
H = GF2Matrix([independent; redundant], 128)
@assert nrows(H) == 135 && rank_gf2(H) == 64
code = matread("codes/rm.128.64.mat")
code["H"] = PCMOpt.to_bool(H)
@assert !any(isodd.(Int.(code["G"]) * transpose(Int.(code["H"]))))
matwrite("codes/rm.128.64.geom.mat", code)
```
